# v0.1.0-stable roadmap — design

This document supersedes the `S1 → S12` table in `docs/README.md`. The original
table was written before Wave 2 packs existed and no longer reflects reality.
This spec defines what "v0.1.0 stable" means in concrete consumer-adoption
terms, the engineering Pack roadmap that gets us there, the release mechanics
that prevent version-pin drift and surprise breakage, and the consumer
migration playbook for `downstream-consumer` and `downstream-consumer`.

## 2. v0.1.0-stable definition

v0.1.0 ships when **both** consumer projects can fully replace their bespoke
scraping code with scrapefold, with no regressions on their respective
replay corpora, after a one-week soak window.

### 2.1 downstream-consumer consumer parity

`downstream-consumer/scripts/sponsorship_audit/markdown_fetch.py` and `enrich_from_site.py`
are rewritten on top of `scrapefold.scrape()` and:

- The 7-day disk cache continues to hit. Delta in hit rate ≤ 5% over a
  200-URL replay corpus committed to `downstream-consumer/tests/scrapefold_parity/`.
- The Telegram / VK fallback (`OG_ONLY_HOSTS` plain-HTTP `og:meta` path) is
  gone. The per-class ladder reclassifies to `requests`-tier when
  JS-heavy engines return suspicious content. If it doesn't, that's a
  scrapefold `classify_url` bug fixed in Pack 7.x, not a downstream-consumer workaround.
- `extract_role_pairs(md)` produces byte-identical `(role, brand)` tuples
  on the replay corpus. Pinned by a parity regression test.

### 2.2 downstream-consumer consumer parity

The scraping paths in `downstream-consumer/services/url_to_text_service.py`,
`services/get_all_URLs_of_website_service.py`, and
`services/process_file_to_array_service.py` are rewritten on top of
`scrapefold.scrape()`, `scrapefold.crawl_site()`, and explicit
`opts.engines=[...]` overrides, and:

- The eight marker-string error returns (`"Frc failed"`, `"Scb failed"`,
  `"Selenium failed"`, `"Jina failed"`, `"Scd failed"`, `"Cloudflare
  failed"`, `"Scrapling failed"`, `"Crawl4AI failed"`, `"Outscraper
  failed"`) are deleted from caller code. scrapefold raises
  `AllEnginesFailed`; the caller wraps one `try/except`.
- The hardcoded per-domain engine mapping (`website_scraper_mapping`) is
  gone. Each surviving entry is either deleted (because `classify_url`
  routes it correctly) or kept as a one-line `opts.engines=[...]`
  override with a comment. **Surviving overrides must be ≤ 3.** More than
  3 = ladder bug, fixed in Pack 7.x.
- Firecrawl `entireWebsite=True` is replaced by
  `scrapefold.crawl_site(url, opts=ScrapeOptions(max_pages=N))`.
  Side-by-side replay on a 50-page corpus shows ≤ 5% page-count delta and
  stitched markdown is byte-comparable modulo Firecrawl-specific
  front-matter.

### 2.3 Out of scope for v0.1.0

Each item below is intentionally **deferred** to v0.2.0 or later. Listed
here so we don't drift mid-pack:

- `RaceStep` / parallel race fan-out in the router.
- MCP server (`scrapefold-mcp` stays a stub).
- Selenium-based pagination (`max_iterations` / infinite-scroll).
- Screenshot capture from inside scrapefold (engines may already populate
  `screenshot_b64`, but no public API surface guarantees it for v0.1.0).
- Parallel LLM-judge merge (`opts.parallel=True` + injected judge
  callable). The ladder replaces this for routing; for benchmarking
  downstream-consumer keeps its current code.
- A dedicated `extract_urls(url) -> list[str]` API. Until v0.2.0,
  downstream-consumer does link extraction in caller via `result.html` + bs4.
- The `obscura` and `brightdata` engines.

### 2.4 Universal release gates

- `./scripts/check.sh` exits 0 on the release commit (ruff lint + ruff
  format + mypy + offline pytest).
- Trusted-publishing CI succeeds end-to-end on `v0.1.0rc1` before the real
  `v0.1.0` tag is cut.
- `CHANGELOG.md` `[Unreleased]` section is empty (everything moved into
  `[0.1.0]`).
- `docs/README.md` "Project status" line reflects "stable, library +
  crawler + CLI."

## 3. Engineering Pack roadmap

Each pack is one alpha bump, one PR/commit train, one Codex review round,
one CHANGELOG section. Each pack opens with a dependency-floor audit
(§4.4).

  cleanup). 13 router tests pass; 381 total green. `RaceStep` entries in
  ladders are skipped with a DEBUG log (TBD for Pack 9 = v0.2.0).
- Land `src/scrapefold/engines/cloudflare.py` — ported from the

  `python -c "from importlib.metadata import version; import scrapefold;

**Estimated:** ~1 day code + 1 Codex round.

### 3.2 Pack 4 — Crawler module → `0.1.0a3`

- `src/scrapefold/crawler/sitemap.py` — parse `/sitemap.xml`, fall back
  to `/robots.txt` `Sitemap:` directive, fall back to same-host BFS.
- `src/scrapefold/crawler/filters.py` — drop `mailto:`, `tel:`,
  `javascript:`, `#` fragments, `utm_*` params, login / share /
  non-HTML paths.
- `src/scrapefold/crawler/stitcher.py` — write a single `.md` file with
  YAML front-matter per page (`url`, `engine`, `elapsed_ms`,
  `fetched_at`) separated by `---`.
- `crawl_site(url, opts)` public API wires sitemap → filters → `scrape()`
  per URL → stitcher.
- TECH_DEBT P1 #3 (per-engine `avg_response_mb` wired through
  `_estimate_step_cost`) and P1 #7 (probe cache module-level dict). Both
  are sequential-walk-relevant and cheap to land here.
- Dep-floor audit + bump.

**Exit:** `await crawl_site("https://docs.example.com",
opts=ScrapeOptions(max_pages=10))` returns a path to a stitched markdown
file; ~30-50 new tests; fixture HTTP server under `tests/fixtures/`.

**Deferred:** P1 #1, #2 (`RaceStep`-coupled). P2 #8, #9 (engine client
reuse — Pack 5, since both are walk-shutdown concerns paired with the
cache).

**Estimated:** ~3 days code + 1 Codex round.

### 3.3 Pack 5 — Disk cache + EnginePool → `0.1.0a4`

- `src/scrapefold/cache.py` — key is `sha256(url) + sha256(opts_canonical_json)`,
  default TTL 7 days, atomic writes via `os.replace`, JSON manifest for
  stats. **Strict canonicalization** (Codex round-1 HIGH): unknown
  types in `opts.extra` bypass the cache with a logged warning rather
  than collapsing to non-deterministic `str(obj)`.
- `src/scrapefold/pool.py` — `EnginePool` (Codex round-1 CRITICAL): a
  lazy engine instance cache whose lifetime spans an entire
  `crawl_site()` call. Router gains `walk(url, opts, *, pool=None)`;
  when called with a caller-owned pool, the router uses it without
  closing. Closes the "per-walk aclose defeats client reuse" trap.
- `scrape()` and `crawl_site()` consult cache when `opts.skip_cache=False`
  (default); bypass when `True`. `crawl_site()` opens one pool and
  threads it through every per-URL `scrape()`.
- `opts.extra["cache_ttl_days"]` per-call override.
- `opts.extra["cache_dir"]` for tests + downstream-consumer compatibility.
- TECH_DEBT P2 #8 + #9: per-instance `httpx.AsyncClient` in HTTP-tier
  engines + SDK client reuse for Firecrawl / Apify / Outscraper.
- Dep-floor audit + bump.

**Exit:** Same URL twice = 1 network call + 1 cache hit. ~20 new tests
covering TTL expiry, atomic-write crash safety, opts-change cache-bust.

**Deferred:** Eviction policy beyond TTL, distributed cache (post-1.0).

**Estimated:** ~2 days code + 1 Codex round.

### 3.4 Pack 6 — Minimal Typer CLI → `0.1.0a5`

- `scrapefold classify <url> [--json]` — returns the `SiteClass`.
- `--json` everywhere; errors fatal with non-zero exit, per

- Dep-floor audit + bump.

**Exit:** `scrapefold scrape https://example.com` returns markdown to
stdout, exit 0. ~15 CLI tests via `typer.testing.CliRunner`.

**Deferred:** Interactive mode, progress bars, MCP server wiring.

**Estimated:** ~1.5 days code + 1 Codex round.

## 4. Release mechanics

Six rules, each enforced by a script or a CI step. No human enforces them
in code review.

### 4.1 Single source of truth for version

- `src/scrapefold/__init__.py:__version__` is canonical.
- `pyproject.toml` uses `dynamic = ["version"]` with
  `[tool.hatch.version] path = "src/scrapefold/__init__.py"`.
- `scripts/check.sh` asserts
  `scrapefold.__version__ == importlib.metadata.version("scrapefold")`.
- A human edits the version in **one** place. Pre-tag drift = red CI.

### 4.2 CHANGELOG gate

- Every PR that touches `src/scrapefold/` must add ≥ 1 line under
  `## [Unreleased]` in `CHANGELOG.md`.
- Enforced by `scripts/check-changelog.sh`: `git diff origin/main...HEAD
  --name-only` includes `src/` ⟹ same diff must include `CHANGELOG.md`
  with a `+` under `[Unreleased]`.
- At pack-close, maintainer renames `[Unreleased]` → `[0.1.0aN]` with
  dated header and opens a new empty `[Unreleased]`. One commit.

### 4.3 Alpha cadence

- One pack = one alpha bump = one tag = one PyPI artifact.
- Tag format: `v0.1.0aN`, `v0.1.0rcN`, `v0.1.0`, `v0.1.x`.
- **No skipping alphas.** Broken pack pre-tag → fix is Pack 4.1, tag is
  still `v0.1.0a(N+1)`. Alphas are cheap; version-history clarity is not.
- **No `--no-verify`, no force-push to `main`, no amending tagged
  commits.** Per global CLAUDE.md ASK-list.

### 4.4 Dependency-floor freshness

- `scripts/check-deps-fresh.sh` reads `pyproject.toml`, queries PyPI's
  JSON API for each direct dep, prints a table of `current-pin /
  latest-stable / staleness (minor versions behind)`.
- Not a CI failure. **Pack-opening checklist item**: the maintainer runs
  it, bumps stale floors, commits with `chore: refresh dependency floors`
  as the first commit of the pack.
- **Policy: lower-bound pins only** (e.g. `httpx>=0.29`), never
  upper-bound, unless there is a known incompatibility documented as a
  code-comment in `pyproject.toml` with the linked issue.
- "Stable" means the **latest published release in the dep's current
  series that is not itself a beta, rc, or alpha**. A dep that is still
  on 0.x (e.g. `crawl4ai`, `cloakbrowser`, `pytest-asyncio`) is fine to
  pin; we just pin to its latest 0.x stable, not to a 0.x-rc.

### 4.5 Tag → publish flow

- `v*` tag on `main` triggers the `publish` job already wired in
  `.github/workflows/ci.yml`. Trusted-publishing is already set up on
  PyPI.
- **Add a release rehearsal job** before tagging: `python -m build &&
  python -m twine check dist/* && pip install dist/*.whl && python -c
  "import scrapefold; print(scrapefold.__version__)"`. Catches
  `pyproject.toml` typos, missing files in `MANIFEST`, dynamic-version
  misconfig before they reach PyPI.
- Rehearsal runs on every PR to `main` (no upload), and again on tag
  (with upload). Same script.
- GH Release auto-drafts from the CHANGELOG section between previous and
  current tag.

### 4.6 Rollback policy

- A published PyPI version is **never deleted** (yanking is OK; deletion
  breaks downstream pins).
- Broken `v0.1.0aN` → ship `v0.1.0a(N+1)` with the fix. Never retag.
- Broken `v0.1.0` → `v0.1.1` within the same day. Both consumers pin
  `^0.1.0` and auto-pick the patch.
- API-rollback (extremely unlikely pre-1.0 with two consumers): tag
  `v0.1.0a(M)` with restored old code, document in CHANGELOG, ask both
  consumers to re-pin.

### 4.7 Files changed by this section

- `pyproject.toml` — `version = "..."` → `dynamic = ["version"]` +
  `[tool.hatch.version]`.
- `scripts/check.sh` — add version-equality check.
- `scripts/check-deps-fresh.sh` — new.
- `scripts/check-changelog.sh` — new.
- `.github/workflows/ci.yml` — add release-rehearsal job +
  changelog-gate step.
- `docs/workflows/releasing.md` — new; documents §4.1–4.6 as a
  per-pack and per-release checklist.

## 5. Consumer adoption playbook

**Order: downstream-consumer first, downstream-consumer second.** downstream-consumer has 2 call sites with
simpler needs → fast feedback on whether the API holds. downstream-consumer has ~12
call sites + marker-string legacy + parallel mode + entireWebsite crawl
→ stresses the surface harder. Sequence inverts risk.

### 5.1 Step 1 — downstream-consumer migration (pin to `0.1.0a4`)

After Pack 5 (cache) lands. Three PRs in downstream-consumer:

- **PR 1 — single-URL replacement:** replace `markdown_fetch.fetch_markdown(url)`
  body with `await scrapefold.scrape(url, opts=ScrapeOptions(render_js=True,
  timeout_s=60, extra={"cache_ttl_days": 7}))` returning `result.markdown`.
  Outer function signature is preserved so callers don't change.
- **PR 2 — fallback removal:** replace `_og_scrape(url)` and its
  `OG_ONLY_HOSTS` gate. Test on `t.me/spartakmoscow`,
  `vk.com/cska_official`, and 3-4 ordinary brand sites. If the per-class
  ladder doesn't auto-handle Telegram / VK, the bug is in scrapefold's
  `classify_url`, not in downstream-consumer.
- **PR 3 — cache removal:** delete `_cache_path`, `_load_cached`,
  `_save_cached` from both files. The cache is scrapefold's job now.

**Parity test:** `downstream-consumer/tests/scrapefold_parity/` runs 200 URLs from
the sponsorship audit corpus through both old code and new code, asserts
`extract_role_pairs(md_old) == extract_role_pairs(md_new)` and
cache-hit-rate delta ≤ 5%.

**Exit gate:** all 3 PRs merged, downstream-consumer CI green, 1 week with zero
scrapefold-attributable issues.

### 5.2 Step 2 — downstream-consumer migration (pin to `0.1.0rc1`)

Start of Pack 7. Four PRs in downstream-consumer:

- **PR 1 — single-URL paths:** `services/url_to_text_service.py` collapses
  8 `get_content_X(url, ...)` functions into one
  `await scrapefold.scrape(url, opts)` call. Per-engine wrappers are
  deleted. Caller signature stays the same to keep downstream stable
  within this PR.
- **PR 2 — marker-string purge:**
  `services/process_file_to_array_service.py` lines 39-43 (marker
  constants) and the chained
  `if html_text == "Frc failed": ...` cascade (lines 448-465) are
  replaced by one `try: ... except AllEnginesFailed: html_text = None`.
  All 8 marker constants and `_is_scraping_failed()` are deleted.
- **PR 3 — per-domain mapping:** `website_scraper_mapping` is reviewed
  entry by entry. Each entry is **deleted** (ladder routes it correctly,
  added to scrapefold's `GOLDEN_CORPUS` as part of the PR) or **kept as
  caller-side override** (`opts.engines=["scrapingdog"]` with a one-line
  comment). Surviving overrides must be ≤ 3; more = ladder bug fixed in
  Pack 7.x.
- **PR 4 — crawl_site:** `entireWebsite=True` Firecrawl path replaced
  by `scrapefold.crawl_site(url, opts=ScrapeOptions(max_pages=N))`.
  Side-by-side replay on the 50-page corpus from §2.2.

**Deferred to downstream-consumer post-v0.1.0** (downstream-consumer keeps its own code for now):
Selenium pagination, screenshot capture, parallel LLM-judge merge,
ScrapingBee `extract_rules` link extraction.

**Exit gate:** all 4 PRs merged, downstream-consumer CI green, 1 week with zero
scrapefold-attributable issues at normal request volume.

### 5.3 Step 3 — Pack 7.x bugfix-only window

Both consumers run on `rc1` in parallel. New scrapefold bugs land as
Pack 7.1, 7.2, … each alpha-bumps to `rc2`, `rc3`, … **No new features.**
Anything that isn't "consumer-blocking regression fix" goes on the v0.2.0
milestone.

Window closes when **either**: 7 calendar days pass with zero
scrapefold-attributable consumer issues **or** both consumer maintainers
explicitly approve the rc.

### 5.4 Step 4 — v0.1.0 cut (Pack 8)

- `__version__` → `0.1.0`, CHANGELOG section closes, tag `v0.1.0`.
- Both consumers bump pin from `0.1.0rcN` (exact) to `^0.1.0` (caret —
  auto-pick patch fixes).
- v0.2.0 milestone opens with: `RaceStep`, MCP, pagination, screenshot,
  parallel LLM-judge, `extract_urls`, `obscura`, `brightdata`. Each gets
  its own Pack.

### 5.5 Migration risk register

| Risk | Mitigation |
|---|---|
| `classify_url` mis-routes a real consumer URL → wrong engine → empty result | Each consumer-migration PR adds its problem URLs to scrapefold's `GOLDEN_CORPUS` as part of the PR. Regression-pinned forever. |
| downstream-consumer cache hit rate drops because `sha256(opts)` key changes when scrapefold normalizes options differently | Pack 5 ships an `opts_canonical_json` doc + test; downstream-consumer's pre-migration cache is invalidated on pin-bump (documented, accepted). |
| downstream-consumer per-domain mapping has > 3 surviving entries → ladder is wrong for real traffic | Land them as scrapefold patch releases (`v0.1.1`, `v0.1.2`). Caller-side overrides are an explicit smell. |
| Firecrawl SDK 4.x → 5.x (or any other upstream major) breaks before v0.1.0 ships | Dep-floor freshness policy (§4.4) catches it at the start of the relevant pack. Worst case: pin upper bound with documented `# Firecrawl 5.x removed AsyncFirecrawlApp.scrape_url — wait for compat fix #N` comment. |
| Parity replay diverges because vendor markdown formatter changes | Replay corpus snapshots compare `text` byte-for-byte, but `markdown` is asserted via `extract_role_pairs` semantic equality, not byte. |

6. `CHANGELOG.md` `[Unreleased]` is empty; `[0.1.0]` has a dated header.
